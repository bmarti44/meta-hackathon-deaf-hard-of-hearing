## 2. Single-mutation rule — H1 does not survive strict reading

GOAL §7: "MUTATE one logged change per child."

- **GEN1-H1 — bundle, self-confessed.** The logged mutation
  replaces parent §§5/7 with: encouragement specification,
  attention control, ITT + IV estimands, exclusion/
  monotonicity/negative-control falsification suite,
  exposure-reported ASL-CDI with dual-SD scaling,
  video-coded validation subset, a conditional morphosyntax
  measure, and §9's take-up inflation — defended as one
  change "because identification and norming jointly define
  one estimand". By that logic any study design is one
  change. Worse, comparison against parent H shows most of
  the "mutation" already exists there: parent §5 already
  specifies offer-randomization, ITT primary, IV secondary,
  stated exclusion/monotonicity with falsification checks,
  contact-time-matched attention control, negative controls,
  and §8 already has `1/(take-up difference)²`. H1 is
  therefore caught on two horns: **if the bundle is one
  mutation, its novel content shrinks to the norming details
  (dual-SD, proficiency-reported scores, morphosyntax cap) —
  a measurement footnote, not the identification advance the
  scorer credits; if the contents are counted honestly, it
  is >1 logged change and breaks the rule.** The scorer's
  "design-adequacy gain" for H1 G3a double-counts parent
  content as child gain.
- **GEN1-Ga / GEN1-F1m — one mutation, two designs.** Each
  logs one change (add concurrent comparison) but leaves it
  as "stepped-wedge **or** concurrent cohort". A design that
  has not chosen its design is not yet the single
  pre-specified study the mutation claims to add. Ga further
  concedes its kill is decidable only "once ratified" —
  "until ratification … verdict = sensitivity-only". So even
  on paper the kill is not yet runnable-to-a-verdict,
  contra the scorer's unqualified "runnable, not run".
  Novelty is also thinner than billed: parent G §5/kill and
  parent F §5/kill already required a prospective comparison
  "vs concurrently measured frozen workup/pathway". Ga/F1m
  add estimand hierarchy and negative controls —
  operational paperwork on a parental requirement.
- **GEN1-A1 — one mutation, specifying facts deferred.**
  Cleanest log (timeline fix explicitly refused as a second
  mutation; G6 FAIL carried). But "fully pre-specified"
  (scorer) / "pinned seeds" (extraction) is false as filed:
  model name/version/mesh/conductivities, seed set,
  per-contact safe-charge limit, and battery floor are all
  "recorded in freeze addendum" / "pinned pre-unblinding".
  What A1 specifies is a *procedure for specifying*. By A1's
  own rule the test stays UNEVALUABLE — the scorer says
  this, then still calls the kill "now *specifiable*", which
  is the correct, weaker word; any stronger paraphrase
  ("evaluable", "runnable") applied to A1 is falsified.
- **All four mutants** also add 2 FMEA delta rows each,
  logged as part of the mutation's consequences. Acceptable
  accounting, noted only because "everything else inherited
  verbatim" is, strictly, already false at §10 of each file.
- **GEN1-P1** is recombinant, so the one-mutation rule does
  not apply; its FMEA deltas D-P1-1…3 are interface
  consequences. No charge.

## 3. Recombination interfaces — legal, empty, partly incoherent

GOAL §7 rule 3 permits a join with "combination data **or** a
stated interface experiment". P1 admits "no pair has
combination data" and states I1–I3 with FAIL rules. The
charge "unevidenced interface passed off as evidenced" is
therefore **not falsified** — P1 never claims evidence.

What a skeptic can still break:

1. **Step 3's narrower prescription is stretched.** Step 3
   §6 enumerated the only Gen 1-legal joins as "a device
   parent (A) × pathway parent (F/G/H) … portfolio". P1's
   actual cross is pathway × pathway (G×H) over frozen, with
   A present only as comparator (§1). GOAL rule 3 arguably
   permits it; the generation's own input record did not
   enumerate it. `fitness-application.md` §6 quietly widens
   the prescription to fit P1 after the fact.
2. **I1's FAIL threshold is not operational.** "Any
   non-eligible child's CI activation delayed beyond
   concurrent frozen median by triage waiting" uses a
   *median* as a per-child harm line — roughly half of any
   concurrent frozen cohort sits beyond its own median, so
   the rule as written cannot distinguish triage delay from
   ordinary spread without the unwritten attribution method;
   its second clause invokes a "pre-set window" that is
   nowhere set. I2's FAIL rides on NI conventions its own
   tables call conventions/sensitivity-only. I3 (zero added
   days) is the only crisp rule. Stated experiments: yes.
   Frozen experiments: no.
3. **Interfaces multiply failure modes, add no evidence.**
   The scorer's own summary stands unbroken: P1 = "two
   INSUFFICIENT parents under one timeline, awaiting
   interface data", with three new ways to fail later.
   Portfolio PASS requiring "component + interface evidence,
   never either alone" is correctly stated and currently
   unsatisfiable twice over.
